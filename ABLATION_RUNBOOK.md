# Ablation Runbook (for an automated agent)

You are running a queue of nine reduced-budget training ablations for the Marathi dialect-MoE ASR project, then regenerating `final.md`. Follow this file top to bottom. Work in `D:\marathi-asr`. The shell is Windows PowerShell 5.1; use `;` to chain commands, not `&&`.

## 1. What you are doing

`final.md` is the results reference for a paper. Its Section 5.6 contains empty `[TBD]` tables for four reviewer questions. The queue trains nine variants and fills them.

| Claim | Question | Runs |
| :--- | :--- | :--- |
| A | Is one training run enough (seed variance)? | `base_s0`, `base_s1`, `base_s2` (3 experts, blocks 5-12, seeds 0/1/2) |
| B | Does cloning the pretrained FFN into experts help? | `scratch_s0` (experts randomly initialised) |
| C | Is 3 experts a finding or a choice? | `k1_s0`, `k2_s0`, `k4_s0` (1, 2, 4 experts) |
| D | Do experts belong in blocks 5-12? | `lower4_s0` (blocks 1-4), `all12_s0` (blocks 1-12) |

Order inside the queue: Stage 1 pretraining re-run (about 30 h), then the nine variants (about 6 h each, 20,000 steps), each followed by its own evaluation. Total about 84 h. The original Stage 1 checkpoints were deleted, which is why Stage 1 is re-run once and shared by all variants.

Reduced budget means absolute WER will be far above the paper's headline 19.50%. Only differences between the nine runs matter.

## 2. Rules

1. Run exactly one training process at a time. Never start a second training or evaluation job while the queue runs; GPU contention slows everything.
2. Do not edit any file in the repository. If something fails, report it (Section 7) instead of patching code.
3. Do not delete anything. The queue deletes old step checkpoints by itself (it keeps the newest 3 per run); that is intended and is the only deletion allowed.
4. Do not edit `final.md` by hand. It is generated by `scripts/build_final_md.py`.
5. Do not change system settings (power plans, scheduled tasks, services) unless the user explicitly says so in chat. Those are listed under Section 8 as optional.
6. Do not start anything not listed here. Do not retry a failed command in a loop.
7. If a check below does not show the expected result, stop and report. Do not continue past a failed gate.

What healthy looks like:
- Stage 1 (`runs\ablations\stage1\stage1.log`): step counter rising toward 18,141.
- First variant `base_s0` (`runs\ablations\base_s0\train.log`) must contain `[Seed] 0` and `[Config] num_experts=3 moe_blocks=[5, 6, 7, 8, 9, 10, 11, 12] expert_init=upcycle aux_weight=0.01`. If a variant starts with the wrong config, stop and report.
- Loss in a running log should fall; `nan` loss or a step counter that stops moving for over 30 minutes is a failure.
- Finished variants appear as `evals\ablations\<name>.json`, about one every 6 hours after Stage 1.

Expected timeline: Stage 1 done after about 30 h; `base_s0.json` appears about 36 h in; the last file about 84 h in.

## 6. If the process stops (crash, reboot, shutdown)

Training saves a checkpoint every 500 steps and the queue resumes from the newest readable one. Check first whether it is really stopped:

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Where-Object { $_.CommandLine -match 'run_ablation_queue|train_moe|pretraining|eval_variant' } | Select-Object ProcessId, CommandLine
```

If no rows are returned and `evals\ablations` does not yet hold all nine JSON files plus the line `ALL DONE` in `runs\ablations\queue.out.log`, restart by running the command from Section 4 again. Finished steps are skipped. Look for `SKIP unreadable checkpoint` in `queue.out.log`; it is normal after a power cut and means the queue fell back to the previous checkpoint.

Do restart at most twice for the same failure. If the same error repeats, stop and report it with the last 40 lines of the relevant log.

## 8. Optional, only with the user's explicit approval in chat

These change system settings; do not run them otherwise.

Restart the queue automatically after a reboot (starts at user logon):

```powershell
schtasks /create /tn "AblationQueue" /sc onlogon /f /tr "cmd /c cd /d D:\marathi-asr && .venv311\Scripts\python.exe -u scripts\run_ablation_queue.py >> runs\ablations\queue.out.log 2>&1"
```

Disable plugged-in sleep while it runs:

```powershell
powercfg /change standby-timeout-ac 0
```

Remove the restart task when the queue is finished:

```powershell
schtasks /delete /tn "AblationQueue" /f
```

- On completion: the table from Section 7 check 3 and the output of the `Select-String` check.
